- Vercel's final vanity rewrite now uses the named `/:path((?!api(?:/|$)).+)` path-to-regexp form, forwarding the captured path to the existing storefront handler and excluding `/api` and `/api/*` without excluding `/apiary`. It remains after the static and explicit public/app rewrites. As a local, temporary-tool check, `@vercel/routing-utils` 6.6.1 compiled this to `^(?:\\/((?!api(?:\\/|$)).+))$` and `/api/storefront?path=%2F$1`; this compilation does not prove a deployed route works. The tool was not added to dependencies. The hosted Preview E2E now tests unpublished query and vanity paths (including an `api`-prefixed salon slug), GET and HEAD 404/noindex, and a published vanity, alongside the existing query and API probes.
- The production Express server now invokes the same storefront handler for public root query selectors before the static homepage, and for unreserved vanity paths after known routes/assets. App/session and private routes remain on their existing shell path. Unknown salons and temporary SSR failures now send `X-Robots-Tag: noindex` even on HEAD. Offline HTTP tests use a test-only public-database fixture, check published/unpublished/outage responses, and make no provider writes. Express is not an emulation of Vercel's full routing pipeline; hosted Preview and later Production probes remain necessary.
- Hosted Preview on commit `305e1d9` passed six query/vanity unpublished GET and HEAD probes (404/noindex), one published vanity probe (200), the responsive audit, and the live-SEO preview check. This is Preview evidence, not Production validation. The older `44acd7c` responsive failure and the later `008b99f` responsive failure remain unexplained: their logs/artifacts redirected to storage inaccessible from this sandbox. Local browser runs passed, which does not establish the hosted failure's cause.
- The responsive hover audit contained a concrete CI timing race: it assumed a Node-side 180 ms or 100 ms wait completed before a 350 ms open timer or 240 ms close timer, respectively. Under load the sleep can overshoot. It now measures the actual browser pointer-to-open and pointer-leave-to-close intervals, still enforcing the minimum delays and real visible/hidden transitions. This addresses an identified failure mode but is not proof it caused either historical failure. The workflow now publishes a separate, fail-closed responsive status with only a sanitized phase, failure kind and script line; it never publishes exception text or page data. The existing storefront smoke report is explicitly labeled as separate.
- A subsequent handler re-audit found that Vercel rewrite query flags were not copied into the internal page URL, so a vanity request with `app`, `customer`, or `customer_ref` could be mistaken for a public salon lookup. The handler now preserves those flags, including empty values, and offline plus hosted-preview regression probes check the platform-shell path. The offline fetch fixture now rejects unexpected external hosts rather than falling through to the real network.
- Template 15's test now asserts that default hero, staff, service, visible gallery and visible reference-video assets exist. Its 30 missing requested images and six process videos remain a creative inventory gap, not necessarily broken URLs: ten colour services share `colour.webp`, gallery uses existing reference images/illustrations, and unprovided process videos are hidden with empty URLs. Owner-approved distinct imagery and authentic footage are still needed; no fabricated replacements were supplied. Uploaded/custom salon assets were not audited by the default-asset test.
- The large-chunk warning remains. `AppRouter` already lazy-loads the full app, and the homepage lazy-loads `TemplatePreviewModal`, whose live preview lazy-loads `SalonWebsitePreview`. The large `main` and preview chunks still require a proper dependency/route waterfall and visual/hydration validation before a broad split; changing Rollup chunking solely to hide the warning could increase initial requests or break shared dependencies. No Core Web Vitals improvement is claimed.
