# Template 03 — inspection and release checks

Scope: Aura Unisex Salon & Wellness Lounge (`unisex_salon`). No site was published, no live migration was applied, and no service, customer or booking record was changed. Other templates and shared dashboard/publishing implementation were not changed; `package.json` only adds the Template 03 test to its existing test command.

## Changes made

1. **Media.** The checkout already contained 51 Aura WebP variants and their source photographs. No original image was recovered or replaced. A new monogram is a fallback, not a recovered original. Saved section media is resolved for the logo, hero, categories, about/why/wellness, booking, service/package overrides, staff, gallery and videos. Broken images use view-only fallbacks; broken customer review photos are hidden. A URL change clears stale `srcSet` metadata, and removing a field does not delete the original Storage object. Unsupported or unavailable videos show an unavailable state.
2. **Editor and storefront.** Saves write only changed section rows; unsaved edits are protected from accidental section switches and reloads. Saved section copy, visibility, ordering, links and buttons, contact/social details, curated reviews, loyalty tiers, and service/staff display overrides reach the storefront. Standalone section order changes DOM order; header/footer and dependent branding, hero-media and button controls stay in their related locations. The planner forwards selected original service/staff IDs and requested date/time rather than editing service records. Display-only offer, reward and staff cards are labelled as informational; actionable offers use the existing Promotions & Offers system.
3. **Browser issues fixed.** The demo toolbar had covered the booking-dialog close button and mobile navigation. Aura now positions its header below that toolbar, puts its mobile drawer outside the transformed header, and raises its booking overlay only when Aura is present.
4. **Empty states.** Empty gallery and filtered-video/service states are explicit rather than blank. Footer links avoid missing in-page targets when their sections are hidden. The editor displays a warning that current server behavior can expose saved edits on a live site.

## Verification performed

- `npm run lint` (TypeScript), `npm run test:template03`, `npm run test:wiring`, `npm run build`, and `git diff --check` passed. Template 03 tests include 100 UI checks, promotion logic/UI tests, and mock Storage/editor/storefront tests. Additional tests exercise changed copy, ordering, a hidden CTA, service/staff display overrides and planner argument forwarding. These are local/mocked, not proof of live RLS, financial calculations or data persistence.
- Headless Chromium: 1440×900, 768×1024 and 390×844, using the demo preview with Supabase responses mocked to empty arrays. Each rendered 52/52 visible images with no horizontal overflow, dead in-page anchors, local HTTP errors, or unmocked JavaScript errors in the recorded runs. Service filters, gallery lightbox/Escape, opening a video dialog with a mocked embed, and opening/closing the booking dialog worked at all three sizes; the mobile menu/navigation worked. The gallery preview was also observed after reload at all three sizes in an earlier run; later Chromium reload attempts were intermittent, so this is not evidence of real saved-media persistence. This is not a full accessibility or device/visual audit.
- Fonts from Google could not be reached in the sandbox (`net::ERR_CONNECTION_CLOSED`); the final interaction run stubbed the font CSS and YouTube embed. Font delivery and actual third-party video playback were not tested. React test renderer emits deprecation warnings, and the all-template wiring test also emitted concurrent-renderer warnings. The production build emitted existing bundle-size and dependency-annotation warnings.

## Release blockers and remaining gaps

1. **Publication control — unresolved.** Existing `202611030001_aura_template03_content.sql` synchronizes section saves to already-published websites, and its public RPC reads saved rows directly. The newly wired storefront consumes that RPC. Thus saving an edit can expose it immediately on an already-published site, conflicting with approval-before-publication. No such live save or publication was performed. Do not deploy/use this editor on a live site until a Template 03 draft/published snapshot and explicit-publish workflow is designed, reviewed and tested. A warning is present in the editor; it is not a technical publish gate.
2. **Storage/security and real data — not verified.** The same pre-existing migration makes the shared `studioflow-media` bucket public and adds public-read access. This work did not apply or change it. An administrator must review existing live bucket visibility, RLS and intended public/private delivery before deployment; do not make private Storage public just to fix permissions. Actual authenticated uploads, tenant isolation, signed URLs, CORS, public delivery and durable refresh require an authorised test account and reachable Supabase. Existing owner URLs and missing/private originals cannot be verified here.
3. **Real customer flows — not tested.** Login/signup/profile, booking availability/confirmation/payment, live contact destinations, external videos and actual promotion redemption require a reachable configured backend and authorised test data. No authenticated account was available. Promotion tests use mocks/local logic and do not establish production policy or redemption behavior. The contact area offers links, not a submitted contact form. Not every editor field and custom-action combination has been exhaustively exercised; section-level concurrent edits lack conflict detection.
4. **Isolation — limited verification.** Changes are scoped to Aura components, Aura-specific helpers/assets and its test command; no live shared setting, original asset, data row or other template code was changed. `npm run test:wiring` passed its mocked/rendered checks across 14 templates, including Templates 01/02; this is not a full live runtime regression.
